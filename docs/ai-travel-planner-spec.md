# AI 여행 일정 웹사이트 설계 및 개발 문서

## 1. 서비스 개요

이 문서는 사용자가 여행지, 일정, 여행 컨셉(가족, 친구, 혼자 등)을 입력하면 AI가 일자별 여행 코스를 자동으로 생성하고, 구글 지도 기반 최적 동선과 로컬 맛집을 함께 추천해 주는 **웹 기반 여행 일정 플래너**의 설계와 개발 가이드를 정리한 것이다.[1][2]
초기에는 웹사이트(반응형 웹)를 1차 목표로 하고, 이후 동일한 백엔드를 활용해 모바일 앱(React Native 또는 Flutter)으로 확장하는 것을 전제로 한다.[3]

---

## 2. 타깃 사용자와 주요 유즈케이스

### 2.1 타깃 사용자

- 여행 계획을 세우는 데 시간이 부족한 직장인
- 가족 여행, 우정 여행, 혼자 여행을 가지만 일정 짜는 것이 번거로운 사용자
- 기존 패키지 여행 대신 **개인 맞춤형 자유여행**을 선호하는 사용자

### 2.2 주요 유즈케이스

1. 사용자가 도시(예: 도쿄), 여행 기간(3박 4일), 여행 컨셉(가족)을 입력한다.
2. 시스템이 해당 도시의 주요 관광지와 이동 시간을 고려하여 **일자별 일정 초안**을 생성한다.
3. 각 일정은 오전/오후/저녁으로 나뉘며, 각 슬롯에 방문 장소와 간단 설명이 포함된다.
4. 하루 단위로 코스를 선택하면 구글 지도로 **최적 경로**(도보/대중교통/차량)를 시각화한다.[4][1]
5. 각 방문 지점 인근의 **로컬 맛집·카페**를 추천 리스트로 제공한다.[2]
6. 사용자는 일정 일부를 수정(장소 교체, 순서 변경 등)하고, 자신의 계정에 저장하거나 공유한다.

## 3. 핵심 기능 정의

### 3.1 사용자 입력 및 검색 기능

- 입력 항목
  - 여행 도시 또는 국가(예: 도쿄, 파리, 제주 등)
  - 출발일/도착일 또는 총 여행일수
  - 여행 컨셉: 가족, 친구, 커플, 혼자, 업무 겸 여행 등
  - 이동 스타일: 여유 있게 / 보통 / 빡세게
  - 대략적인 예산(선택)
- 요구 사항
  - 자동완성(예: 주요 도시 검색) 지원
  - 기본 입력만으로도 일정 생성 가능하도록 필수/선택 항목 구분

### 3.2 일자별 여행 코스 자동 생성

- 규칙 기반 + 지도 데이터 활용을 1차 목표로 한다.[5]
- 과정 개요
  - 도시별 주요 POI(관광지, 랜드마크, 박물관, 자연 명소 등) 데이터 확보
  - POI별 메타데이터: 예상 체류 시간, 추천 시간대(오전/오후/야간), 카테고리(가족 친화, 쇼핑, 자연 등)
  - 여행일수 × 하루 허용 방문 수(예: 3~5곳)를 기준으로 POI를 분배
  - Google Distance Matrix 또는 Directions API를 활용해 이동 시간 계산 후, 하루 단위로 동선이 효율적인 코스를 구성한다.[1][4]
- 향후 확장
  - LLM 기반 AI 엔진을 붙여 일정 초안을 재배치·보완하고, 사용자 피드백에 따라 코스를 자동 조정하는 기능 추가.[5]

### 3.3 지도 및 최적 경로 시각화

- Google Maps JavaScript API를 사용해 웹에서 지도를 표시한다.[6][1]
- Directions API를 활용해 출발지(숙소) → 경유지(관광지, 식당 등) → 도착지(숙소 혹은 다음 숙소) 경로를 계산한다.[1]
- `waypoints`와 `optimize:true` 옵션을 사용하여 하루 일정 내 여러 장소의 방문 순서를 자동 최적화한다.[4]
- 결과는 지도 상 폴리라인(경로)과 마커(장소)로 시각화하고, 이동 수단(도보/차량/대중교통) 선택 옵션을 제공한다.[6]

### 3.4 로컬 맛집 및 카페 추천

- Google Places API의 Nearby Search 기능을 사용하여 특정 좌표 주변의 `restaurant`, `cafe` 등 타입의 장소를 검색한다.[7][2]
- 필터링 조건
  - 평점, 리뷰 수, 가격대 등의 기준으로 상위 N개 후보를 선정
  - 여행 컨셉에 따라 가족 친화적, 혼자 가기 좋은, 인스타 감성 등 태그를 활용한 필터링(향후 ML/태깅 데이터 필요)
- 화면 표현
  - 지도 상 아이콘과 함께 리스트 카드(이름, 평점, 리뷰 수, 거리, 대표 사진)를 제공

### 3.5 계정 및 일정 관리

- 기능
  - 이메일/소셜 로그인
  - 생성한 일정 저장, 수정, 복제, 삭제
  - 일정 공유(링크 복사, PDF/이미지 내보내기 등은 추후 단계)
- 권한
  - 비로그인 사용자도 일정 생성은 가능하되, 저장/수정은 로그인 시 지원

## 4. 화면 설계(와이어프레임 수준)

### 4.1 메인 페이지

- 요소
  - 상단 헤더: 로고, 로그인/회원가입 버튼, 언어 선택(한국어/영어 등)
  - 메인 검색 폼
    - 여행지 입력(자동완성)
    - 출발일/도착일 또는 일수 선택
    - 여행 컨셉, 인원, 이동 스타일 드롭다운
    - "여행 일정 만들기" CTA 버튼
  - 하단에는 서비스 특징(자동 일정 생성, 최적 동선, 로컬 맛집 추천 등) 소개 섹션

### 4.2 일정 결과 페이지

- 좌측: 일자별 일정 리스트
  - 1일차, 2일차, 3일차 탭 또는 아코디언 구조
  - 각 일자별로 시간대(오전/오후/저녁) 구분과 장소 카드(이름, 간단 설명, 예상 체류 시간)
- 우측: 구글 지도
  - 선택된 일자의 코스를 폴리라인과 마커로 시각화
  - 지도 내에서 장소 클릭 시 상세 정보(사진, 주소, 리뷰 링크 등) 표시

### 4.3 맛집 추천 패널

- 특정 타임슬롯(예: 점심) 또는 특정 장소 주변의 맛집을 보여주는 사이드 패널/모달
- 리스트 항목: 식당명, 평점, 리뷰 수, 카테고리, 예상 가격대, 지도에서의 위치
- 선택 시 일정에 식당을 추가할 수 있는 버튼 제공

### 4.4 마이페이지

- 나의 일정 리스트: 썸네일, 도시명, 날짜, 생성일
- 일정 상세 보기/편집
- 계정 설정(언어, 선호 여행 스타일, 기본 숙소 타입 등)

## 5. 기술 스택 및 아키텍처

### 5.1 프론트엔드

- React + Next.js (TypeScript 권장)
- 스타일링: Tailwind CSS 또는 Material UI
- Maps 연동: Google Maps JavaScript API + `@googlemaps/js-api-loader` 패키지 사용[8][6]

### 5.2 백엔드

- Node.js + Express 또는 NestJS (혹은 Python + FastAPI, 팀 선호도에 따라 선택)[3]
- 주요 역할
  - 일정 생성 비즈니스 로직 구현
  - Google Maps/Places API 호출 (API 키 보호)
  - LLM API(OpenAI 등) 연동을 통한 설명 문구 생성 및 일정 튜닝
  - 인증/인가 처리(JWT 등)

### 5.3 데이터베이스

- PostgreSQL 또는 MySQL
- ORM: Prisma, TypeORM 등 선택[3]
- 초반에는 Supabase/Firebase 같은 BaaS도 고려 가능

### 5.4 외부 서비스 연동

- Google Maps JavaScript API: 지도 렌더링 및 경로 시각화[6]
- Google Directions API / Distance Matrix API: 경로 및 이동 시간 계산[4][1]
- Google Places API: 주변 맛집 및 POI 검색[2][7]
- LLM API: 일정 설명, 일정 재구성, 추천 문구 생성

### 5.5 아키텍처 개요

- 클라이언트(Next.js)
  - UI 렌더링, 사용자 입력 처리, 지도의 기본 렌더링
- API 서버(백엔드)
  - `/itineraries/generate` : 일정 생성 요청 처리
  - `/places/nearby` : 맛집·POI 검색 위임
  - `/auth/*` : 로그인/회원가입/토큰 갱신
- DB
  - 사용자, 일정, POI 메타데이터 저장

## 6. API 설계 예시

### 6.1 일정 생성 API

- `POST /api/itineraries/generate`
- 요청 바디

```json
{
  "destination": "Tokyo",
  "startDate": "2026-05-01",
  "endDate": "2026-05-04",
  "concept": "family",
  "pace": "relaxed",
  "budgetLevel": "medium"
}
```

- 응답 예시(요약)

```json
{
  "days": [
    {
      "dayIndex": 1,
      "date": "2026-05-01",
      "slots": [
        {
          "timeOfDay": "morning",
          "placeId": "poi_123",
          "title": "도쿄 타워",
          "description": "도쿄 시내를 한눈에 볼 수 있는 전망대...",
          "stayMinutes": 120,
          "location": { "lat": 35.6586, "lng": 139.7454 }
        }
      ]
    }
  ]
}
```

### 6.2 주변 맛집 검색 API

- `GET /api/places/nearby`
- 쿼리 파라미터: `lat`, `lng`, `radius`, `type`(restaurant/cafe 등)
- 내부적으로 Google Places Nearby Search를 호출하여 결과를 가공 후 반환한다.[7][2]

### 6.3 일정 저장/조회 API

- `POST /api/itineraries` : 일정 저장
- `GET /api/itineraries/:id` : 일정 상세 조회
- `GET /api/itineraries?userId=...` : 특정 사용자의 일정 목록 조회

## 7. 데이터베이스 설계(초안)

### 7.1 주요 테이블

| 테이블 | 설명 |
|--------|------|
| users | 사용자 계정 정보 |
| itineraries | 일정 메타(도시, 날짜, 컨셉 등) |
| itinerary_days | 일정의 일자별 정보 |
| itinerary_slots | 각 일자 내 타임슬롯(장소 단위) |
| places | 자체 관리하는 POI 메타데이터(선택 사항) |

### 7.2 간단 스키마 예시

- `users`
  - id (PK)
  - email, password_hash, name, created_at, updated_at
- `itineraries`
  - id (PK)
  - user_id (FK to users)
  - destination_city, start_date, end_date, concept, pace, created_at
- `itinerary_days`
  - id (PK)
  - itinerary_id (FK)
  - day_index, date
- `itinerary_slots`
  - id (PK)
  - day_id (FK)
  - time_of_day (morning/afternoon/evening)
  - title, description, place_external_id (Google Place ID 등)
  - lat, lng, stay_minutes
- `places`(선택)
  - id (PK)
  - external_place_id (Google Place ID)
  - name, category, default_stay_minutes, rating, user_tags

## 8. 개발 단계 로드맵(MVP → 확장)

### 8.1 1단계: MVP (기본 웹사이트)

- 메인 페이지 + 일정 결과 페이지 UI 구현
- 단일 도시(예: 도쿄) 대상으로 하드코딩된 POI 리스트를 이용한 간단 일정 생성 규칙 구현
- Google Maps JavaScript API로 지도 및 마커 표시[6]
- Directions API로 하루 일정의 경로를 시각화(waypoints 최적화 포함)[1][4]

### 8.2 2단계: 맛집 추천 및 계정 기능

- Places API를 이용한 주변 맛집/카페 추천 기능 추가[2][7]
- 이메일/소셜 로그인, 일정 저장/조회 기능 구현
- UI에서 일정 편집(장소 교체, 순서 변경) 기능 추가

### 8.3 3단계: 다국적 도시 지원 및 AI 고도화

- 지원 도시/국가 확장, POI 메타데이터 수집·정비
- LLM API를 통해 설명 문구 자동 생성, 일정 재배치·튜닝 기능 추가[5]
- 사용자 피드백(좋아요/별점)을 반영하여 추천 품질 개선

### 8.4 4단계: 모바일 앱 확장

- 동일한 백엔드 API를 사용하여 React Native 또는 Flutter 기반 모바일 앱 개발[3]
- 지도 및 경로 시각화는 각 플랫폼의 Google Maps SDK 사용
- 푸시 알림(다음 일정 알림, 체크인 알림 등) 기능 추가

## 9. 운영 및 확장 고려사항

- Google Maps/Places API 사용량에 따른 비용 관리와 쿼터 모니터링 필요[7][6]
- 캐싱 전략: 자주 조회되는 도시/POI/맛집 데이터를 DB 또는 캐시 레이어(Redis 등)에 저장하여 응답 속도 및 비용 최적화
- 로그 및 분석: 사용자의 검색 패턴, 일정 선택/수정 패턴을 수집해 추천 알고리즘 개선에 활용
- 보안: API 키 보호(백엔드에서만 사용), JWT 기반 인증, HTTPS 적용

## 10. 결론

본 문서는 AI 기반 여행 일정 웹사이트의 전반적인 기능 요구사항, 화면 구조, 기술 스택, API 및 DB 설계를 한눈에 볼 수 있도록 정리하였다.
이 문서를 기반으로 와이어프레임 제작 → UI 구현 → 백엔드 API 개발 → 지도/Places 연동 → AI 기능 추가의 순서로 개발을 진행하면, 이후 모바일 앱 확장까지 자연스럽게 이어지는 구조를 갖출 수 있다.[1][3]
