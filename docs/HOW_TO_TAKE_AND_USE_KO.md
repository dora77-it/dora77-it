# 이걸 가지고 가서 어떻게 쓰는지 (실전 인계 가이드)

질문: **"그다음 어떻게 해야 하니? 이걸 가지고 가서"**  
답: 아래 7단계를 그대로 따라하면 됩니다.

---

## 1) 확장 폴더만 복사
인계할 때는 `extension/` 폴더만 전달하면 됩니다.

- 포함 파일
  - `manifest.json`
  - `popup.html`, `popup.css`, `popup.js`
  - `background.js`
  - `content.js`
  - `README_KO.md`

---

## 2) 상대방 PC에서 설치
1. Chrome 열기
2. 주소창에 `chrome://extensions` 입력
3. **개발자 모드 ON**
4. **압축해제된 확장 프로그램 로드**
5. 전달받은 `extension/` 폴더 선택

---

## 3) 최초 실행 체크
1. `https://labs.google/fx/tools/whisk` 접속
2. Google 로그인/세션 확인
3. 확장 아이콘 클릭
4. 테스트 프롬프트 1~3개 입력 후 **시작**

---

## 4) 안 될 때 (90% 해결 루틴)
1. Whisk 탭이 열린 상태에서 실행했는지 확인
2. 팝업의 `입력창/생성버튼/결과이미지` 셀렉터 확인
3. 타임아웃 `120000` → `180000`으로 증가
4. 딜레이 `1500` → `3000`으로 증가
5. 확장 재로드 후 재시도

---

## 5) 인계 시 꼭 같이 전달할 것
- 현재 잘 동작하는 셀렉터 3개
  - input selector
  - generate selector
  - image selector
- 추천 설정값
  - timeoutMs
  - delayMs
- 실패 사례 1~2개와 해결 방법

---

## 6) 배포 형태 2가지
### A. 내부용(가장 쉬움)
- 소스 폴더 그대로 전달
- 각자 개발자모드에서 로드

### B. 외부 공유용
- ZIP으로 묶어 전달
- 설치 가이드 문서 같이 제공

> 참고: Chrome Web Store 배포는 별도 심사/정책 절차가 필요합니다.

---

## 7) 다음 고도화 우선순위
1. 실패 항목 자동 재시도(1~2회)
2. 작업 로그 다운로드(JSON/CSV)
3. 이미지 파일명 규칙 고도화
4. 언어 토글(한국어/영어/일본어)

여기까지 하면 “인계 가능한 실사용 MVP” 상태입니다.
