## 소개
**고든테의 AI 캐비넷**은 Whisk AI 작업을 자동화하는 도우미입니다.
반복적인 이미지 생성 작업을 더 적은 수동 클릭으로 처리할 수 있습니다.

## 핵심 기능
- 프롬프트 대량 큐 처리
- 생성 이미지 자동 다운로드
- 일시 오류 자동 재시도
- 멀티 버전 실행 모드 지원

## 지원 언어 (3개만 지원)
1. 한국어
2. 영어
3. 일본어

## 빠른 시작 (크롬 확장 버전)
1. 확장 프로그램을 Chrome/Edge/Brave에 설치합니다.
2. 브라우저 툴바에서 확장 프로그램을 실행합니다.
3. 실행 모드/버전을 선택합니다.
4. 프롬프트를 붙여넣거나 `.txt` 파일을 불러옵니다.
5. **Start** 버튼을 누릅니다.

> 권장 설정: 브라우저의 "다운로드 전에 저장 위치 확인" 옵션을 꺼두면 연속 저장이 더 안정적입니다.


## ❓ 꼭 크롬 확장으로만 해야 하나요?
아니요. **크롬 확장은 필수가 아닙니다.**

당장 선택지는 3가지입니다.
1. **크롬 확장(MV3)**: 브라우저 안에서 바로 실행, UI 만들기 쉬움
2. **Playwright CLI(권장 시작점)**: 무료/빠른 구현, 코드로 자동화 제어 쉬움
3. **Electron 데스크톱 앱**: 앱 형태 배포에 유리, 확장 없이 사용 가능

### 어떤 걸 고르면 되나요? (빠른 의사결정)
- "나는 개발 빨리 시작 + 비용 최소" → **Playwright CLI**
- "브라우저 안에서 버튼 누르는 UX가 필요" → **크롬 확장**
- "설치형 앱으로 배포하고 싶다" → **Electron**

> 결론: 예산이 적다면 `Playwright CLI`로 MVP를 먼저 만들고, 필요할 때 확장 프로그램으로 확장하는 게 가장 현실적입니다.

## ⚙️ 자동으로 돌아가는 원리 (크롬 확장 기준)
확장 프로그램이 자동화하는 흐름은 아래 6단계입니다.

1. **프롬프트 수집**: 입력창/`.txt`에서 프롬프트 목록을 읽음
2. **작업 큐 생성**: 프롬프트를 순서대로 큐에 적재
3. **Whisk 실행 제어**: 현재 프롬프트를 Whisk에 입력하고 생성 요청
4. **완료 감지**: 로딩 상태/결과 이미지 노출 여부를 감지
5. **자동 다운로드**: 결과 이미지를 파일명 규칙대로 저장
6. **오류 복구**: 타임아웃/네트워크 오류 시 재시도 후 다음 큐 진행

즉, 사람이 하는 반복 작업(입력→생성→저장→다음)을 스크립트가 대신 수행하는 구조입니다.

## 💡 돈 적게 들이는 대안: 확장 프로그램 없이 자동화 가능?
네, 가능합니다. 아래처럼 **크롬 확장 외 방식**도 선택할 수 있습니다.

| 방식 | 비용 | 난이도 | 장점 | 단점 |
|---|---:|---:|---|---|
| Playwright/Selenium 스크립트 | 무료 | 중 | 유연하고 강력함 | UI 변경 시 유지보수 필요 |
| Electron 데스크톱 앱 | 저비용 | 중상 | 확장 없이 앱처럼 배포 가능 | 초기 세팅 시간이 더 필요 |
| 반자동 매크로 + 수동 검수 | 무료/저비용 | 하 | 가장 빨리 시작 가능 | 완전 자동화가 어려움 |

### 추천 경로 (돈 적게 들이는 순서)
1. Playwright로 MVP 구현(무료)
2. 안정화 후 Electron으로 감싸 배포
3. 필요하면 확장 프로그램 버전 병행

### 시작 팁
- 먼저 10~20개 프롬프트 소량으로 테스트
- 실패 로그(프롬프트/시간/오류 메시지) 저장
- 서비스 약관 위반 가능성이 없는 범위에서 속도 제한 적용

## 🔩 실제로 "생성 + 다운로드"가 되는 기술 원리
질문하신 포인트를 한 줄로 정리하면:
**확장 프로그램(또는 자동화 스크립트)이 Whisk 웹페이지를 사람이 하듯 조작하고, 결과 이미지 URL을 잡아서 다운로드 API로 저장**하는 방식입니다.

### 내부 동작 (실전 버전)
1. **입력 주입**: content script가 Whisk 입력창(`textarea`)에 프롬프트를 넣음
2. **생성 트리거**: 생성 버튼 클릭 이벤트를 발생시킴
3. **완료 대기**: 로딩 스피너 종료/결과 DOM 등장/네트워크 응답 중 하나를 조건으로 완료 판정
4. **결과 수집**: 생성된 이미지 요소(`img`)의 `src` 또는 다운로드 링크를 수집
5. **다운로드 실행**: background/service worker가 `chrome.downloads.download()`로 파일 저장
6. **큐 다음 작업**: 성공/실패 상태 기록 후 다음 프롬프트 실행

> 포인트: 클릭 자동화는 content script, 파일 저장은 background가 담당하면 안정적입니다.

## 🧱 나는 이걸 어떻게 실체화하지? (가장 현실적인 순서)
### 1단계: MVP 범위 고정 (반드시 작게)
- 프롬프트 10개 처리
- 이미지 1장/프롬프트
- 실패 시 1회 재시도

### 2단계: 파일 구조 만들기 (크롬 확장)
- `manifest.json` (권한/스크립트 등록)
- `background.js` (큐 상태, 다운로드 처리)
- `content.js` (Whisk 페이지 조작)
- `popup.html/js` (Start/Stop, 프롬프트 입력)

### 3단계: 이벤트 흐름 연결
- Popup `Start` 클릭 → background에 작업 큐 전달
- background가 현재 탭에 `content.js` 실행 지시
- content가 생성 완료 시 이미지 URL 반환
- background가 다운로드 실행 후 다음 작업 호출

### 4단계: 실패 복구 넣기
- 타임아웃(예: 90초) 초과 시 실패 처리
- 실패 항목 1회 재시도 후 스킵
- 로그(JSON) 저장: `prompt`, `status`, `error`, `time`

### 5단계: 안정화
- UI 셀렉터가 바뀌어도 대응 가능하도록 셀렉터 상수 분리
- 요청 간 딜레이(속도 제한) 추가
- 소량 테스트 → 중량 테스트(10 → 50 → 200)
